Named cause: on Windows, 'python3' is a Microsoft Store app-execution alias.
It RESOLVES on PATH and then fails every invocation, so a 'command -v python3'
probe reports success and the run dies later instead of degrading.

$ python3 -c "print(1)"   # the alias, as the runner meets it on a Windows box
Python was not found; run without arguments to install from the Microsoft Store, or disable this shortcut from Settings > Manage App Execution Aliases.
exit=49
$ command -v python3      # ...yet it resolves, which is what the old probe asked
/tmp/nm-pystub/python3
