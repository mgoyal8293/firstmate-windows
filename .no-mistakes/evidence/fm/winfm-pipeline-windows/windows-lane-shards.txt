Windows CI workflow, as the real YAML consumer sees it
=====================================================
  job windows-lint: runs-on=windows-latest timeout=18m matrix=-
  job windows-behavior: runs-on=windows-latest timeout=40m matrix={'shard': [1, 2, 3, 4]}

The matrix declares 4 shards, and FM_WINDOWS_LANE is built from
strategy.job-total, so the lane names the runner is actually asked for are:
    windows-1of4
    windows-2of4
    windows-3of4
    windows-4of4

union of the four shards == the whole lane : True  (39 scripts, disjoint)
worst shard 15.48 min vs the job's 40 min timeout -> 2.58x margin
whole lane run serially would be 61.9 min, which does NOT fit 40 min

A matrix that disagrees with the runner is refused rather than silently dropping tests:
$ bin/fm-test-run.sh --list --lane windows-1of8
fm-test-run: lane 'windows-1of8' asks for 8 windows shards but this runner is configured for 4 (see --list-lanes)
exit=2
$ bin/fm-test-run.sh --list --lane windows-5of4
fm-test-run: lane 'windows-5of4' shard index is outside 1..4 (see --list-lanes)
exit=2
